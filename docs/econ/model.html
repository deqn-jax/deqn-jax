Write your own model

A model is a folder of short Python files that state its variables, its calibration and its equilibrium conditions. This page reads the files of the running example and then lists the steps from a copy of them to a solved model of your own.

The running example, Brock–Mirman with endogenous labor and a cap on hours (described on the first page), lives in src/deqn_jax/models/bm_labor_constrained/. It extends the model without a cap, bm_labor, and borrows from it everything that the cap does not change: the definitions of output, consumption and factor prices, the law of motion, the steady state, and the distribution from which simulations start. Its own folder therefore holds three files. Docstrings are left out below; the code is otherwise as it appears in the repository.

variables.py: states, decisions, calibration

src/deqn_jax/models/bm_labor_constrained/variables.py
import jax.numpy as jnp

from deqn_jax.models.bm_labor.variables import CONSTANTS as _BM_LABOR_CONSTANTS
from deqn_jax.models.variable_spec import VariableSpec

SPEC = VariableSpec(state_names=("k", "z"), policy_names=("sav_rate", "L"))

State and decisionsThe state is capital \(K\) and log productivity \(z\). The decisions are the savings rate \(s\) and hours \(L\). The program learns one function from the state to the decisions; every other variable is computed from these.

L_OUT_BOUND = 1.01
L_MAX = 1.02

Two labor numbersL_OUT_BOUND is the largest value the hours rule can take. L_MAX is \(\bar L\), the cap in the complementarity condition. With the cap above the largest attainable hours, the cap never binds at this calibration; the first page lowers \(\bar L\) to 1 in its run configuration so that it does.

CONSTANTS = {**_BM_LABOR_CONSTANTS, "L_max": L_MAX}

CalibrationA dictionary of parameters. It takes the calibration of bm_labor, \(\alpha = 0.36\), \(\beta = 0.99\), \(\delta = 0.1\), \(\psi = 1\), \(\theta = 1\), \(\rho = 0.9\), \(\sigma = 0.04\) and log utility, and adds the cap.

POLICY_LOWER = jnp.array([1e-6, 1e-6])
POLICY_UPPER = jnp.array([1 - 1e-6, L_OUT_BOUND])

N_SHOCKS = 1

DESCRIPTION = (
    "Brock-Mirman with endogenous labor and an upper labor cap (Fischer-Burmeister)"
)

BoundsThe savings rate lies in \((0, 1)\) and hours in \((0, 1.01]\). The rule’s outputs are squashed into these intervals, so consumption stays positive at every state without further care. One shock, to productivity. DESCRIPTION is the line shown by deqn-jax list.

equations.py: the equilibrium conditions

src/deqn_jax/models/bm_labor_constrained/equations.py
from typing import Dict

import jax.numpy as jnp
from jax import Array

from deqn_jax.models._complementarity import fischer_burmeister
from deqn_jax.models.bm_labor.equations import definitions
from deqn_jax.models.bm_labor_constrained.variables import SPEC

EQUATION_NAMES = ("euler", "labor_foc")

EquationsTwo equilibrium conditions, one per decision: the Euler equation for savings and the labor condition with the cap.

def equations(
    state: Array,
    policy: Array,
    next_state: Array,
    next_policy: Array,
    constants: Dict,
) -> Dict[str, Array]:
    beta = constants["beta"]
    delta = constants["delta"]
    psi = constants["psi"]
    theta = constants["theta"]
    L_max = constants["L_max"]

    p = SPEC.unpack_policy(policy)
    defs = definitions(state, policy, constants)
    next_defs = definitions(next_state, next_policy, constants)

Today and tomorrowThe function receives today’s state and decisions and, for one value of next period’s shock, tomorrow’s state and decisions under the same rule. It returns each condition as an error that is zero in equilibrium. definitions turns a state and decisions into output, consumption, the wage and the marginal product of capital.

    u_c = defs["u_c"]
    w = defs["w"]
    u_c_next = next_defs["u_c"]
    mpk_next = next_defs["mpk"]

    euler = u_c - beta * u_c_next * (1.0 + mpk_next - delta)

Euler equation\(u'(C_t) - \beta\, u'(C_{t+1})(1 + r_{t+1} - \delta)\). The program evaluates this error at each quadrature node for next period’s shock and takes the weighted average, which gives \(u'(C_t) - \beta\,\mathbb{E}_t[\dots]\). Write each condition so that the expectation enters linearly, as here; the weighted average is then the conditional expectation.

    slack = L_max - p.L
    wedge = w * u_c / (psi * jnp.power(p.L, theta)) - 1.0
    labor_foc = fischer_burmeister(slack, wedge)

    return {"euler": euler, "labor_foc": labor_foc}

The constraintThe slack \(\bar L - L_t\) and the wedge \(\mu_t = w_t u'(C_t) / (\psi L_t^\theta) - 1\) must both be non-negative with a zero product. fischer_burmeister(a, b) returns \(\sqrt{a^2 + b^2} - a - b\), which is zero exactly when \(a \ge 0\), \(b \ge 0\) and \(ab = 0\). Below the cap the wedge is zero and the usual labor condition holds; at the cap the slack is zero and the wedge is positive. The plain condition \(\psi L^\theta = w\,u'(C)\) would have no zero at the cap.

The borrowed definitions and law of motion

For completeness, the two borrowed functions that carry economics. From src/deqn_jax/models/bm_labor/equations.py:

def definitions(state: Array, policy: Array, constants: Dict) -> Dict[str, Array]:
    s = SPEC.unpack_state(state)
    p = SPEC.unpack_policy(policy)

    alpha = constants["alpha"]
    gamma = constants["gamma"]

    Z = jnp.exp(s.z)
    # Cobb-Douglas: Y = Z * L^(1-alpha) * K^alpha
    y = Z * jnp.power(p.L, 1.0 - alpha) * jnp.power(s.k, alpha)

    # Factor prices
    mpk = alpha * Z * jnp.power(p.L, 1.0 - alpha) * jnp.power(s.k, alpha - 1.0)
    w = (1.0 - alpha) * Z * jnp.power(p.L, -alpha) * jnp.power(s.k, alpha)

    # Consumption via savings rate out of output
    c = (1.0 - p.sav_rate) * y
    sav = p.sav_rate * y

    u_c = jnp.power(c, -gamma)

    return {"Z": Z, "y": y, "mpk": mpk, "w": w, "c": c, "s": sav, "u_c": u_c}

And the law of motion, built in src/deqn_jax/models/brock_mirman/dynamics.py and shared by the Brock–Mirman family:

        # Capital accumulation
        k_next = (1 - delta) * s.k + defs["s"]

        # TFP shock
        eps = shock[:, 0] if shock.ndim > 1 else shock
        z_next = rho_z * s.z + sigma_z * eps

        return jnp.stack([k_next, z_next], axis=1)

From a copy to a solved model

  1. Copy the folder under a new name, and in the copy replace bm_labor_constrained by the new name in the imports and in name=.

    cp -r src/deqn_jax/models/bm_labor_constrained src/deqn_jax/models/my_model

  2. Change the economics. New states or decisions go into SPEC, parameters into CONSTANTS, bounds into POLICY_LOWER and POLICY_UPPER, and one error per decision into equations. If the definitions, the law of motion or the steady state change as well, copy those files from bm_labor into your folder and import them from there.

  3. Register the model by adding two lines to src/deqn_jax/models/__init__.py, an import next to the others and an entry in the _MODELS dictionary:

    from deqn_jax.models.my_model import MODEL as _my_model
...
    "my_model": _my_model,

    The model should now appear in uv run deqn-jax list, and uv run deqn-jax info my_model prints its states, decisions and equations.

  4. Train it. Copy configs/bm_labor_cap.yaml to configs/my_model.yaml, set model: my_model and checkpoint_dir: runs/my_model, remove the constants: block, and run

    uv run deqn-jax train --config configs/my_model.yaml

    The trained rule is saved in runs/my_model/ every 5,000 rounds and at the end.

  5. Read the results. The first command simulates 10,000 periods under the trained rule and prints the distribution of each equation’s error on a \(\log_{10}\) scale; the second computes impulse responses to each shock.

    uv run deqn-jax evaluate runs/my_model/checkpoint_020000.eqx
uv run deqn-jax irf runs/my_model/checkpoint_020000.eqx --girf -o irf_out

    The evaluator reports the errors in the units in which equations returns them. The unit-free Euler error of the first page divides the Euler error by marginal utility; scripts/dev/econ_figures.py shows how.

Everything else, including models without an analytical steady state, constraints inside an expectation, other shock processes, the network and training settings and the programming interface, is described in the reference documentation: implementing a model and the full model contract.
